Cheque Payouts — Jira-ready stories

Epic allocation: new Cheque Payouts epic; Jira key not yet assigned. Its stories have document IDs, not invented Jira keys.

This set contains 28 stories. It covers cheque settings, three capture modes, the full destination selector, name comparison/resolution, daily spending, automatic completion and notifications. It reuses the shared foundation owned by Manual Bank. Cheque depends on the listed foundation stories rather than completion of Manual Bank export/CSV work.

The name threshold defaults to 0.7; a score of 0.7 is Match. For permitted no-ID payouts, use the captured name and explicitly display “Name is not verified using ID documents”. Both-role collection may submit either, both or neither cheque field; both fields are required before authorisation. In-progress payouts retain their threshold and original wait. Completion is automatic after all required review, name-check, wait and daily-limit checks pass. Cheque amounts count toward client and venue daily totals for now, without automated bank execution.

CHE-01 — Enable Cheque and add its controls to the shared venue screens

Epic: Cheque Payouts — new epic, Jira key not yet assigned

Jira placement: New — Cheque epic; extend the shared venue screens owned by Manual Bank

Previous combined reference: replaces JUS-03.

Dependencies: MBT-01, MBT-02, MBT-05, MBT-06.

User story: As an Admin or Super Admin, I want to enable Cheque for a venue, so that Collectors can offer this approved destination.

UI description: Add Cheque Enabled and the cheque collection-mode control to the Admin venue screen, Super Admin All Venues → click venue → Payout Destinations screen, and Strapi. Reuse the same Save and Cancel controls.

Acceptance criteria:

  • Saving the enabled switch makes Cheque available for new submissions at that venue in the full destination-selection flow.
  • Enabling Cheque requires one saved collection mode; missing mode shows a validation message.
  • The switch reflects the saved value on reopening. Cancelling does not enable the option.
  • Other venues keep their settings; staff can complete already submitted payouts using the recorded destination.
  • Admin access remains restricted to permitted venues; Super Admin can configure the selected venue across clients through All Venues.
  • Show the same saved cheque settings on all authorised surfaces. The global threshold remains a separate Super Admin setting.
  • The shared screen, permissions and Save/Cancel framework are implemented once in the Manual Bank epic; this story adds cheque-specific fields and validation.

CHE-05 — Set the global cheque name-match threshold

Epic: Cheque Payouts — new epic, Jira key not yet assigned

Jira placement: New — global Super Admin setting

Previous combined reference: replaces JUS-11.

User story: As a Super Admin, I want to configure the global fuzzy name-match threshold, so that all venues use a consistent comparison rule.

UI description: Super Admin global settings shows Cheque Name Match Threshold with default 0.7, help text, Save and Cancel. Explain that changes apply to new payouts and do not re-evaluate payouts already in progress.

Acceptance criteria:

  • Only Super Admins can change the global value; Admins cannot edit it through their venue screen or a direct request.
  • Require a numeric value between 0 and 1 inclusive. Explain that 0.7 is 70% similarity and higher values require closer similarity.
  • A score greater than or equal to the saved threshold is Match; a lower score is No match. With default 0.7, 0.70 is Match and 0.69 is No match.
  • Saving sets one global value for new payouts across venues and records who changed it and when. Cancel keeps the saved value.
  • Retain the threshold applicable when a payout starts. Later global changes do not alter in-progress comparisons, Match/No match outcomes or recorded Authoriser resolutions.
  • Completed payout records retain the score and threshold used for their decision.

Confirmed rule / scope note: D5 confirmed — threshold changes affect new payouts only; in-progress payouts and recorded Authoriser resolutions retain their original threshold.

CHE-17 — Show cheque and recipient names with their similarity

Epic: Cheque Payouts — new epic, Jira key not yet assigned

Jira placement: New — cheque name comparison

Previous combined reference: replaces JUS-24.

User story: As a Collector, Approver or Authoriser, I want to compare the cheque name with the recipient name and see how closely they match, so that I can assess a name difference and understand whether ID documents verified the comparison name.

UI description: Show Cheque Name and the comparison name together with Name Similarity percentage, applied threshold, and Match or No match in capture, summary and review. Label the comparison name Verified ID Name when verified, or Captured Name with “Name is not verified using ID documents” when no ID document was submitted.

Acceptance criteria:

  • Use the name from successful ID verification when available. When no ID document was submitted, compare against the recipient name captured with address and date of birth under CHE-19.
  • For captured names, display “Name is not verified using ID documents” beside the comparison name, including when the result is Match.
  • Ignore capitalisation, leading/trailing or repeated spaces, and common punctuation when comparing names. Preserve the original entered names for display and history.
  • Allow reordered full name parts to be equivalent: John Smith and Smith John are treated as the same full name.
  • Treat initials and missing name parts as partial similarities rather than equivalent full names: John Smith and J Smith, or John Michael Smith and John Smith, receive partial comparison scores.
  • Representative equivalent-name examples are John Smith / JOHN SMITH, John Smith / John Smith, Anne-Marie / Anne Marie, and John Smith / Smith John.
  • Apply the threshold retained for this payout under CHE-05. At default 0.7, scores of 0.70 and 0.71 show Match and 0.69 shows No match.
  • Classify using the actual score and keep the displayed percentage consistent with the outcome; rounding must not make a below-threshold result appear to meet the threshold.
  • Explain that the score measures name similarity, not confidence that identity has been verified.
  • Use Unable to compare when required inputs or a comparison result are unavailable, as in CHE-19.

Comparison examples:

For example, should these differences affect the score?

  • John Smith / JOHN SMITH: capitalisation.
  • John Smith / John Smith: extra spaces.
  • Anne-Marie / Anne Marie: punctuation.
  • John Smith / Smith John: name order.
  • John Smith / J Smith: initials.

The agreed rules above treat the first four as equivalent names and initials as a partial similarity.

Confirmed rule / scope note: D4 confirmed — ignore capitalisation, extra spaces and common punctuation; allow reordered full names; treat initials or missing name parts as partial similarities. Exact partial-match percentages depend on the chosen consistent matching method; verify and document them rather than inventing scores.

CHE-24 — Automatically complete a cheque payout after all requirements are met
